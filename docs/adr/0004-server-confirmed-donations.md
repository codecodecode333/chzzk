# 후원은 서버가 먼저 주문을 만들고, 결제사 승인 확인 후에만 확정한다

후원은 돈이 걸린 기록이므로 브라우저가 보내는 성공 신호를 믿지 않는다. 결제 전에 서버가 후원 주문(주문 번호, 후원자, 방송, 그 시점의 받는 사람, 금액)을 `대기`로 만들어 금액과 수신 대상을 고정하고, 결제 후에는 서버가 토스페이먼츠 결제 승인 API를 시크릿 키로 호출해 상태 `DONE`·총액·주문 번호가 주문과 일치할 때만 `확정`한다. 성공 리다이렉트·새로고침·웹훅 재시도로 같은 승인 통지가 여러 번 와도, 주문 번호·paymentKey 유니크 제약과 `대기 → 확정` 조건부 원자 갱신, 결제사 `Idempotency-Key`로 한 번만 확정한다. 합계는 `확정`된 주문만 더한다.

## Considered Options

- **클라이언트 성공 콜백으로 확정**: 구현은 쉽지만 금액·수신 대상을 위조할 수 있고 과제 요구("화면의 성공 표시만으로 확정하지 말 것")에 어긋난다.
- **웹훅만으로 확정**: 웹훅은 개발자 계정마다 등록해야 하고 공개 URL이 필요하며 서명도 없어, 웹훅은 보조 경로(재조회 후 같은 확정 로직)로만 둔다.
- **주문서형(결제위젯) 키**: 주문 번호로 결제 조회가 안 되어 만료 주문 재확인에 불리하므로 결제창(API 개별 연동) 키를 쓴다.

## Consequences

- 결제 인증 후 10분 안에 승인해야 하므로 성공 리다이렉트 경로가 주 경로다. 응답 없이 남은 `대기` 주문은 30분 뒤 `만료`되지만, 결제사 조회로 `DONE`이 확인되면 늦게라도 확정한다.
- 결제사 호출은 `PaymentGateway` 인터페이스 뒤에 두어 테스트에서 가짜로 대체한다. 자동 테스트는 가짜 게이트웨이만 쓰고 토스를 호출하지 않는다.
- 토스 문서의 공개 샘플 테스트 키는 더 이상 쓸 수 없다(`UNAUTHORIZED_KEY`). 실제 테스트 모드 결제는 개발자 본인의 무료 토스페이먼츠 개발자 계정에서 받은 `test_ck_`/`test_sk_` 키로 한다. 서버는 `test_` 키가 아니면 명시적으로 허용하지 않는 한 시작하지 않는다.
- 환불·취소·정산은 이 결정 범위 밖이다.
